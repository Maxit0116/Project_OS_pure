# S2.0.4 — Open Project OS Workbench in Void

**Ticket:** S2.0.4  
**Applies to:** External Void fork (`projectos-void-fork` or team fork)  
**Workbench:** `projectos/workbench` standalone Vite app

## Goal

Register a Void command that opens the Project OS workbench in a webview panel:

- **Dev:** `http://localhost:5173` (run `cd projectos/workbench && npm run dev` first)
- **Prod (later):** static `file://` or bundled assets from `projectos/workbench/dist`

## Prerequisites

1. Void fork builds on macOS (see `docs/void-adoption-notes.md` S2.0.1)
2. Workbench dev server running on port 5173
3. Gate 0 decision: Continue (see `docs/gate-0-decision.md`)

## Step 1 — Add command contribution

Copy the snippet from [`projectos.openWorkbench.contribution.json`](./projectos.openWorkbench.contribution.json) into the Void extension `package.json` under `contributes.commands` (merge with existing commands).

Suggested command id: `projectos.openWorkbench`  
Title: `Project OS: Open Workbench`

## Step 2 — Register handler

Use [`openWorkbenchHandler.ts`](./openWorkbenchHandler.ts) as reference. Adapt import paths to your Void fork layout.

Typical registration site (implemented 2026-07-08):

- `src/vs/workbench/contrib/projectos/browser/projectos.contribution.ts` — `registerAction2`
- `src/vs/workbench/contrib/projectos/browser/projectosWorkbenchPanel.ts` — `IWebviewWorkbenchService`
- `src/vs/workbench/workbench.common.main.ts` — side-effect import

Legacy reference only (extension API, not used in workbench_contrib path):

- `src/vs/workbench/contrib/projectos/browser/projectos.contribution.ts` (new contribution)
- Or minimal patch in an existing extension entry point

Handler behavior:

```
if process.env.PROJECTOS_DEV === '1':
  url = 'http://localhost:5173'
else:
  url = file://.../workbench/dist/index.html  # after npm run build
open webview panel with url
```

## Step 3 — Dev workflow

```bash
# Terminal 1 — workbench
cd projectos/workbench
npm install
npm run dev

# Terminal 2 — Void
cd projectos-void-fork
PROJECTOS_DEV=1 ./scripts/code.sh

# In Void: Command Palette → "Project OS: Open Workbench"
```

1. `cd projectos/workbench && npm run build`
2. Copy `dist/` into Void resource bundle or serve via `file://`
3. Remove `PROJECTOS_DEV` dependency for packaged builds
