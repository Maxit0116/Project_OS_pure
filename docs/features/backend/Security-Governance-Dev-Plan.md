# Security：执行治理开发计划

**状态**：SEC-0–SEC-3 已落地（2026-10-20）。本地工具门禁已经够用。审批写在工作区审计记录里，不引入账号系统。  
**范围**：模型可以提议操作，服务器决定是否执行，并且事后能查到谁被允许、谁被拒绝。  
**总计划**：[`Backend-Dev-Plan.md`](Backend-Dev-Plan.md)。SEC-1 放在 Phase 3，与 Loop 真执行同一阶段。  
**锚点**：

- ToolPolicy：`services/harness/tool-policy.ts`、`.projectos/permissions.json`，Deny > Ask > Allow。
- 软沙箱分类：`services/harness/shell-sandbox.ts`。
- 写范围：叶子 `allowedWritePaths`，apply 前还有身份再校验。
- 密钥：`high-confidence-secret-patterns`、网关 `redaction.ts`。记忆写入也会拒绝密钥样貌。
- 不可信数据：编排器和 `grounded-answer-service.ts` 把仓库内容放进不可信边界，要求不当成指令。
- 检索围栏：`RETRIEVAL_FENCE_NOTICE`。外部文档默认关闭。
- worktree 合并：必须 `confirm: true`。

**对标一句话**：提示词里的「不要做危险的事」不是安全边界。边界是 Policy、路径约束和审批记录。

## 0. 现状

本地单用户没有登录。这在当前产品里是合理的，不是 Phase 1 缺口。

已经成立的边界：

- 未知工具 deny。
- MCP 和 shell 默认不执行，除非规则 allow，或验证命令集已被批准。
- 检索 quote、记忆、规则以外的行走文件，都被写成非指令、非授权。
- 模型不能靠输出路径来给自己加写权限。

还没有的：

- 一条跨 run 的审计日志。策略事件只有挂到某次 run 时才出现在 Agent Flow。
- 高风险操作的持久审批。验证批准有哈希，但是否使用文件存储并不统一。
- 对「仓库里的文字要求执行工具」的机械隔离。今天靠围栏和「工具不由这段文字直接调用」。一旦 Route ② 打开，这个假设会失效。Route ② 继续关闭，就是在维持这条隔离。

## 1. 切片

### SEC-0 — 维持提议和执行分离

**目标**：新功能不能把模型输出接成直接 `spawn` 或直接写盘。

- [x] 代码评审约定写进 Harness README 已有的第 1 条旁边：Loop、修复重试、符号索引都不得新增执行入口。
- [x] H5 的第二次生成仍然经过 validate 和 Policy。
- [x] 不增加「信任本次运行」的全局开关。

**验收**：一次修复重试若指向写范围外路径，结果与第一次一样被拒绝。

### SEC-1 — 审批记录

**目标**：ask 被同意或拒绝之后，重启仍能解释原因。

- [x] 记录工具名、匹配规则、命令集或路径哈希、决定、时间、`runId`。不记录命令输出和密钥。
- [x] 验证命令集继续用现有哈希。本切片要求生产调用使用文件存储。
- [x] 拒绝也要记录。没有记录的 allow 视为没批准。
- [x] worktree 合并的 `confirm: true` 写入同一类记录。

**验收**：批准过的命令集在重启后仍可执行。没记录的 shell 不会因为上次进程内存里允许过就再执行。

### SEC-2 — 审计事件

**目标**：从一次运行能看到允许、拒绝、写入和验证，而不只看到模型文本。

- [x] 追加到该 run 的 JSONL：`tool_policy_decision`、apply、验证证据 id、审批 id。
- [x] 事件里的路径用工作区相对路径。脱敏沿用现有红线。
- [x] 不建独立的安全信息与事件产品，不接外部 SIEM。

**验收**：一次被拒绝的 MCP 调用在 run 事件里能找到 deny 原因。事件文件里没有 API key 原文。

### SEC-3 — 不可信内容清单

**目标**：把已经散落的围栏列成一份调用方必须遵守的表。不新做检测模型。

- [x] 清单包括：功能图与项目描述、文件正文、检索 quote、外部文档、记忆索引、会话摘要、工具输出、网页或 MCP 文本。
- [x] 这些内容可以出现在用户消息或数据块里，不能拼进系统规则段。
- [x] 外部文档和 MCP 保持默认关闭。

**验收**：新增一种上下文时，清单和装配测试一起更新。只改提示词、不改位置，不算完成。

### 明确不做

| 项 | 原因 |
|----|------|
| 账号、团队角色、SSO | 没有多用户部署 |
| 租户隔离、密钥托管服务 | 同上。本地密钥仍在 `SecretStore` |
| 用分类器自动放行高风险 shell | 与「不默认 Run Everything」冲突 |
| 承诺靠提示词挡住间接注入 | 注入文本不能获得工具调用权；做不到的语言不做 |

## 2. 依赖

SEC-0 是约束，和 H5 一起落地。SEC-1 依赖 Verification 的命令集哈希。SEC-2 依赖 Session 的 JSONL 已经是运行的事实来源。

## 3. 不变量

- 模型输出不是授权。
- Deny 优先于 Ask，Ask 优先于 Allow。
- 未批准不执行。执行失败不能记成批准。
- 审计和审批记录不包含密钥、原始推理和完整文件正文。
- 打开 Route ② 之前必须重新审查 SEC-3。本计划不授权打开它。
